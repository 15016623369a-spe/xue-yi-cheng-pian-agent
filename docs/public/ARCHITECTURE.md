# 架构与执行机制

[返回 README](../../README.md)

## 架构定位

当前实现是由文字模型规划、人工编辑与本地确定性执行器组成的工作流 Agent。模型负责知识与讲稿改编，程序负责协议校验、可用素材登记、任务状态和媒体生成。没有运行时任意工具选择的 ReAct 循环，也没有向量库或完整的多 Agent 协作系统。

已有媒体能力从实际课程制作中抽取，当前独立项目直接调用 Remotion、FFmpeg 和本地语音工作进程，不通过 MoneyPrinterTurbo 总装。

## 模块职责

| 模块 | 主要职责 |
| --- | --- |
| `web.py` | 回环 HTTP 服务、JSON API、静态页面与受控媒体下载 |

| `alignment.py` / `pronunciation.py` | 原文与 ASR 对齐、术语读法、字幕切分与弹字锚点 |

| `cleanup.py` / `workers/watermark_ocr.swift` | 本机文字水印识别、FFmpeg区域修补、原件与音轨保留、恢复及摘要缓存 |

| `workers/` | 隔离运行 MLX 音频模型和数值同步检测 |

## 项目数据与边界

工作台的 `workspace.json` 包含原始 `source`、创作 `brief`、`knowledge`、`storyboard`、媒体 `config`、当前 `revision` 和 `approved`。修订快照保存在项目 `revisions/`。

知识与分镜的关联示例：

```json
{
  "id": "S01",
  "title": "为什么可以复用旧结果？",
  "knowledge_ids": ["K01"],
  "speech": "先比较输入内容摘要，再判断旧结果能不能复用。",
  "analogy": {
    "mapping": "备菜代表可复用的阶段结果。",
    "boundary": "软件仍需检查输入和产物，不能只看文件存在。"
  },
  "visual": {
    "template": "flow",
    "steps": [{"label": "输入摘要"}, {"label": "阶段结果"}],
    "conclusion": "按依赖复用"
  },
  "events": [{
    "id": "E01", "anchor": "输入内容摘要",
    "popup": "检查输入", "sound": "beep", "seconds": 1.6
  }]
}
```

- `Kxx` 知识必须有原文依据；`Sxx` 必须引用已提取知识且覆盖全部知识。
- 每个事件锚点需要在该镜口播中恰好出现一次，避免歧义。
- 模型只返回受支持字段，不能直接指定任意本机路径、导入音频或随机种子。
- 实际渲染前合并可信的媒体配置，并再次做项目 schema 校验。
- `figure`、音效、视频与表情素材通过资源登记引用，文件存在与类型仍要核验。

当前模板为 `flow`（2–4 步）、`branch`（1–2 处理步骤及旁路）、`calculation`（1–4 行）、`figure`（已登记图片）。主视频宽高比限制为 16:9，封面则独立支持横竖布局。

## 模型链路

```text
source + brief + prompt version
        ↓
知识提取 → 原文行号选择 → 程序回填逐字引文 → 校验
        ↓
受众改编 → 讲稿 / 图解 / 类比边界 / 事件 → 校验
        ↓
可编辑草稿 → 人工审阅 → 制作配置
```

知识提取和分镜改编各至多一次结构修正，整次任务共用四次 HTTP 请求上限，包含连接重试。生成事件触发句先按唯一逐字重合尝试修复，再严格校验；提取和分镜分别保存检查点，失败后可复用有效步骤。已有结果只有输入摘要和提示词版本符合、产物通过核验时才复用。详见 [自动纠错与失败恢复](AUTO_RECOVERY.md)。

出处校验只证明引文来自所选原文，不证明知识判断正确，也不能证明类比不会误导。人工审阅是流程中的独立步骤。

## 执行与缓存

```text
每镜：voice → asr → prepare / align → render → mix → mux
                                         ↓
整片：可选 opening + 各镜中间片 → export → audit
```

准确依赖以 `engine.py` 每个 `step` 的输入为准。配置、对应内容与资产摘要、实现文件指纹及运行环境身份共同参与缓存键；缓存命中还要逐个验证已登记文件的 SHA-256。

`Store` 把阶段结果写入暂存目录。成功后计算文件哈希、原子登记；失败产物不作为成功缓存。SQLite 保存 run 和 attempt，便于区分新建、命中与失败。项目锁和媒体锁控制本机并发，避免同时写入同一制作状态。

导入旧配音需要讲稿、音色身份、随机种子、音频及转写文件哈希与登记一致；不能只把任意 WAV 放到目录里就跳过合成。

音色身份不包含仅用于后处理的语速和音量。调整音量时可以复用声音生成与转写，但要更新混音和相关下游。模型运行身份包含模型配置和权重文件清单；没有在每次阶段运行时重新计算数 GB 权重的完整哈希。

任务失败后保留成功阶段，下次重试重新检查依赖和文件。它不是任意工具异常都会自动修好的系统：缺少工具、错误参考声音或不合格转写仍需修正输入。

## 音频、字幕与动效

- Qwen3-TTS 在独立 MLX 进程生成短句；生成预算、尝试次数有限。
- Whisper 提供 ASR 及字词时间信息，门禁检查覆盖、末句、数值和部分异常重复。
- 原文保留原有技术词，`pronunciations` 只影响合成读法；对齐逻辑把读法时间映回原文字幕。
- 事件时间由口播锚点和 ASR 对齐产生，再映射到实际帧率。
- 短句边缘进行平滑；背景音乐、事件音效与人声独立控制。
- 各镜使用 PCM 中间音频，最终统一 AAC，避免分段 AAC 填充在长片中累积。
- 同步检测对导出音轨和预期混音进行相关性检查。主动静音场景可明确跳过，不能伪报测得零偏移。

ASR 可能错认技术词；这些检查不能证明语音没有所有瑕疵。审核记录应区分自动检查、抽帧、人类试听与知识审阅。

## 素材检索与封面

素材匹配优先参考本地名称、标签和文字上下文，缺少候选时再查 Commons 图片。单次最多两次模型请求、六组查询；已有素材保留，弱匹配留空。下载受域名、TLS、大小和解码校验约束，保存来源、作者、许可及匹配理由。

这是**有限范围的图片检索**，不是全网短视频抓取或逐帧理解。资源库不扫描用户整台电脑，也没有自动提取任意平台受限视频的能力。

横竖封面按尺寸独立渲染和校验，再成对登记。第二张失败不会把整组标为完成，重试可复用已成功的第一张。封面修订与视频修订分开，换封面无需重做配音和整片。

## 本地数据与接口保护

系列偏好保存在本机`.web/creation.json`，不写死到渲染组件。项目的`theme.series`与`title`分别控制系列和单期名称。`titles`与`cleanup`使用已有持久任务、输入快照及项目修订保护：标题候选生成不直接改稿；采用候选、替换素材需要匹配当前修订，并清除原审阅。

新增接口：`GET/POST /api/preferences`；`GET/POST /api/projects/<id>/titles`；`POST /api/projects/<id>/titles/apply`；`POST /api/projects/<id>/cleanup`。清理只接受项目已登记的素材键及受限相对区域坐标，不接收任意文件路径。原件以独立资产键保留，隐藏于自动匹配目录之外。自动识别不确定时返回待处理状态；项目冲突不覆盖新编辑。正式清理媒体采用PCM中间音频，浏览器预览另用AAC。

- 默认监听 `127.0.0.1`；校验 Host、Origin 和本地请求 token。
- 资源读取限于已登记路径，不把网页请求路径直接作为任意文件访问入口。
- 远程模型请求保留证书与主机名校验，不跟随携带密钥的重定向。
- 模型密钥仅保存本地所有者可读写文件，不通过设置读取 API 返回。
- 编辑带修订号；内容变化取消旧审阅，过期提交返回冲突。
- 后台任务记录自己的输入设置，不把最新草稿误当旧视频的实际制作参数。

上述措施服务于本地使用，并不等于完成多用户互联网服务的鉴权、隔离或安全审计。


## 网上片头检索

片头使用独立的 `opening` 后台任务，与静音表情素材分开处理。`web/opening.js` 提供常驻入口，收集人物、关键词、原话、情绪、平台和期望时长；后台通过 B站公开搜索 HTML 与搜索引擎收录的抖音页面提取具体视频页。链接与标题来自实际响应，不让文字模型编造视频 ID。候选只说明文字匹配理由，不自动确认人物身份、情绪或原话。

接口提供 `search`（只查候选）、`search_apply`（最多尝试前两条并接入）和 `import`（按选择接入）三种模式。选定候选后，yt-dlp 获取指定区间。可手动填写剪点，或在起点后最多90秒进行本机 Whisper 转写；指定原话至少三个有效字符，归一化后唯一匹配才自动裁切，重复则显示多个时间点供选择。PCM MOV 供正式制作，AAC MP4 供网页预览；追加时将现有片头和新片段规范到同一时间基准后串联。单片段0.5–30秒、串联总长不超过60秒，当前准备规格为1280×720/30fps、单声道24kHz。

检索、导入和导出分别记录状态。自动尝试未成功时返回 `needs_input`，不把候选当成已接入；手动和自动接入都保存当前应用结果。新项目默认无片头，表达方向不触发默认片头。替换或移除片头会取消原审阅，重新导出后才生成对应修订的成片；交付页按 `source_revision` 区分当前与历史结果。

检索缓存10分钟；原片下载、转写、准备后的媒体分别绑定输入摘要，复用前核对文件哈希。转写与其他本机媒体任务共用锁。只有媒体完成并通过解码检查、且项目修订号仍匹配时才登记片头；项目期间有修改就保留任务结果，不覆盖新版本。检索无需文字模型密钥，也不会调用模型 API。详见 [网上找片头](OPENINGS.md)。
